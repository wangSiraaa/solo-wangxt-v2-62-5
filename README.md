# 儿童椅实体资源预约与排座系统

把“现场儿童椅”从抽象占位升级为**可追踪实体资源**：每把椅子独立建账、有完整状态机；儿童宾客（包括匿名儿童）必须绑定具体椅子后才能占桌；自动/手工排座同时校验桌容量、锁定、关系组与儿童椅库存；资源故障或停用绝不悄悄挪动已布置/已锁定席，只产生阻断级“方案待处理”，由人工替换或撤销。

## 运行

```bash
npm test     # Node 内置测试运行器，无需安装依赖
npm start    # http://localhost:4173
```

浏览器使用 IndexedDB 本地持久化；核心引擎同构，Node 测试使用事务化内存库。

## 资源模型

### 椅子状态机

| 状态 | 含义 | 典型流转 |
| --- | --- | --- |
| `available` 可用 | 在库可分配 | 预留/导入/修复/归还 |
| `reserved` 已预留 | 绑定有效预约但未摆场 | 布置 / 释放后回可用 |
| `deployed` 已布置 | 现场已摆到对应桌卡 | 归还 / 故障 / 停用 |
| `returned` 已归还 | 归还终态（预约侧） | 椅子回 `available` |
| `fault` 故障 | 不可用；若占用中则开阻断问题 | 修复回原预约状态 |
| `retired` 停用 | 报废撤回；若占用中则开阻断问题 | 人工换椅或撤销预约 |
| `pending_verification` 待核验 | 旧项目占位迁移的实体账，未现场核验 | 核验后回已预留/可用 |

### 关键实体

- `chairs`：实体椅子（编号、标签、归属桌、状态、核验信息、旧项目引用）。
- `guests`：成人/儿童宾客；匿名儿童以 `anonymous=true` 保存，**同样必须绑定椅子**。
- `reservations`：儿童椅预约，含 `reserved/deployed/returned/released`、`locked`、乐观版本与完整 `history`。
- `assignments`：成人桌位分配。
- `issues`：阻断/提示级问题（`chair_fault`、`chair_retired`、`verification_needed`）。
- `operations`：幂等请求与成功响应；`audits`：全部成功/失败操作审计；`migrations`：迁移记录。

## 业务规则

1. **儿童席不可超卖**：预留只接受 `available` 椅子；浏览器 IndexedDB 读写事务与内存库串行队列保证并发争抢只有一个成功。
2. **桌容量**：成人分配 + 有效儿童预约（有桌卡）共同计数；锁定桌拒绝新增。
3. **锁定**：锁定预约不能普通换桌/释放；锁定椅子故障/撤回时席次与锁定均不动，仅开问题。同桌人工换椅允许（换资源不换席）。
4. **关系组**：同组必须同桌。自动排座把未入座整组作为一个单元；手工换桌默认把同桌的整组成员一起移动，否则报 `GROUP_SPLIT` 并回滚。
5. **故障/撤回不静默移动**：`markChairFault` / `retireChair` 只改资源状态并把项目置为 `pending`；存在阻断问题时自动排座直接拒绝。人工路径：同桌换椅（关闭问题）、修复保留原椅（关闭问题）、解锁后撤销。
6. **幂等**：所有写操作必须带 `idempotencyKey`；同键同参返回首次结果，同键异参报 `IDEMPOTENCY_CONFLICT`；执行失败不占用幂等键。
7. **事务回滚**：每个用例在单个跨表事务内完成；校验失败或中途资源不足整体恢复。成功审计与数据同事务；失败审计用独立事务留痕。

## 旧项目本地迁移

`migrateLegacyProject(db, legacy, { idempotencyKey })` 输入：

```json
{
  "project": { "id": 2025, "name": "旧活动" },
  "tables": [{ "id": 1, "name": "家庭桌", "capacity": 4, "locked": true }],
  "childChairs": [{ "id": 9, "label": "旧库存椅", "tableId": 2 }],
  "guests": [
    { "id": 2, "name": "小宝", "type": "child", "tableId": 1, "childChairPlaceholder": 1 }
  ]
}
```

迁移保证：

- 每个占位生成一把 `pending_verification` 实体椅 + 一条绑定它的有效预约，ID 带 `leg_` 前缀且重跑幂等。
- 容量沿用旧桌（旧桌定义缺失时按引用人数补建并给警告）；锁定桌与锁定占位继承锁定。
- 原桌卡关系保留；成人分配保留；匿名儿童保留匿名身份；迁移产生非阻断“待核验”问题，不影响项目为 `open`。
- 现场核验后椅子回到“已预留”状态（因为预约有效），再可走正常布置/替换流程。

## 导入导出

- **椅子批量导入**：资源页粘贴 JSON 数组，支持 `available` / `pending_verification` 等合法状态；已有有效预约的椅子导入自动跳过，不扰动现场方案。
- **椅子导出**：当前项目椅子资源 JSON，可作为批量导入模板。
- **全项目导出/导入**：页面右上角导出含项目、桌、宾客、椅子、预约、分配、问题、审计的快照；导入在浏览器本地库恢复。

## 界面

- **桌位可视化**：桌容量、锁标识、成人/儿童席、绑定椅子编号与状态、待处理问题、未绑定实体椅的儿童清单。
- **宾客与椅子资源**：新增桌/宾客（含匿名儿童）、椅子批量导入导出、故障/停用/修复/核验/归还。
- **自动排座诊断**：只读预案列出每组目标桌、需要的椅子数、阻断错误与警告；执行时全成或全败。
- **历史记录**：按操作类型筛选，成功/失败、错误码、操作人、对象与参数详情均可见。

## 验收场景（`npm test`）

1. 两把实体椅分别预留，重新读取仍保持。
2. 最后一把椅并发争抢仅一个成功；同幂等键重放不产生第二单；异参冲突报错。
3. 换桌目标无可用椅：`CHAIR_EXHAUSTED`，原桌、原椅、原状态完整保留；批量换座中途失败整组回滚。
4. 已布置/已锁定资源故障：席次不动、项目进入 `pending`、自动排座拒绝；人工换椅后新椅继承“已布置”，问题关闭。
5. 旧项目占位迁移为待核验资源：容量、锁定、原桌卡、匿名身份保留；重跑无重复；核验后回到已预留；导出审计完整。
